# 世界 RPG 0.94a 五槽存档读档逻辑

## 功能范围

当前实现位于 `s2/data/war3map.j`，提供 5 个本地角色存档槽。

- 开局先显示本地存档菜单，不直接进入选英雄。
- 可以加载已有角色，或者绑定一个槽位后新建角色。
- 输入 `-save` 后，将原保存系统生成的职业存档代码写入当前槽位。
- 下次进入地图选择同一槽位时，从本地文件读取代码并交给原读档系统。
- `-asave` 账号物品存档仍走原流程，不写入角色槽。
- 本功能不替代原保存和读档算法，只负责本地槽位文件及多人同步。

## 本地文件

保存目录：

```text
TWRPG\AutoSave\
```

每个槽位使用以下文件：

```text
slotN_count.pld   存档代码段数量
slotN_meta.pld    职业名、等级和代码段数量
slotN_code0.pld   第 1 段完整存档代码
slotN_code1.pld   第 2 段完整存档代码
...
```

在允许旧文本输出的运行模式下，还会生成：

```text
slotN_view.txt
```

`view.txt` 只用于人工查看，不参与自动读档。核心数据是 `count.pld` 和 `codeX.pld`。

## 全局状态

五槽逻辑使用以下 `AS_*` 全局变量：

- `AS_ACTIVE_SLOT[playerId]`：玩家当前绑定的槽位，范围为 1 到 5。
- `AS_PLAY_NAME`：临时使用玩家名传输字符串时的名字备份。
- `AS_TABLE`：同步代码段、按钮编号等临时数据。
- `AS_SAVE_DIR`：本地文件目录 `TWRPG\AutoSave\`。
- `AS_CHUNK`：每个 PlayerName 分片长度，当前为 30。
- `AS_DIALOG`：每个玩家的槽位 Dialog。
- `AS_MENU_PAGE`、`AS_MENU_SLOT`：当前菜单页和选中的槽位。
- `AS_STARTUP_MENU`：菜单是否来自开局流程。
- `AS_PENDING_NEW`：等待进入选英雄流程的新建请求。

使用的同步 native：

```jass
DzSyncData
DzTriggerRegisterSyncData
DzGetTriggerSyncPlayer
DzGetTriggerSyncData
```

同步前缀为 `twslotload`。

## 开局和菜单流程

地图开局函数 `l6O1i` 原本直接调用：

```jass
call lOipi(Player(Ouqo))
```

当前改为：

```jass
call AutoSlot_ShowStartupMenu(Player(Ouqo))
```

菜单流程：

1. `AutoSlot_ShowStartupMenu` 显示 5 个槽位。
2. `AutoSlot_SlotLabel` 读取 `count` 和 `meta` 文件生成槽位名称。
3. 点击槽位后，`AutoSlot_ShowActionMenu` 显示操作页。
4. `[1] 加载角色` 调用 `AutoSlot_Select`。
5. `[2] 使用该存档新建角色` 调用 `AutoSlot_RequestNew`。
6. `[0] 取消` 返回槽位列表。

命令入口：

```text
-slot       打开槽位菜单
-slot 1     直接读取槽位 1
-slot 2     直接读取槽位 2
...
-slot 5     直接读取槽位 5
```

`AutoSlot_Init` 在 `main` 末尾通过以下代码初始化：

```jass
call ExecuteFunc("AutoSlot_Init")
```

## 新建角色流程

选择“使用该存档新建角色”后：

1. `AutoSlot_RequestNew` 将 `slot + 1` 写入 `AS_PENDING_NEW[playerId]`。
2. 使用 `ExecuteFunc("AutoSlot_RunPendingNew")` 延后调用，避开 JASS 函数声明顺序限制。
3. `AutoSlot_RunPendingNew` 设置 `AS_ACTIVE_SLOT[playerId]`。
4. 调用当前版本原选英雄入口 `lOipi(Player(playerId))`。
5. 玩家完成选英雄后，该槽位成为后续 `-save` 的写入位置。

选择槽位本身不会覆盖文件。只有成功执行 `-save` 后才会写盘。

当前新选择的英雄会在 `ioI9i` 的 `i_qO` 新英雄分支中设为 100 级。读档创建英雄时传入 `false`，不会被该逻辑覆盖等级。

## 保存流程

原保存命令入口仍为：

```text
-save
```

原保存系统完成代码生成后进入 `i96ii`。该函数会遍历已完成的保存进程，并设置：

```jass
set llql[Ii1o]=LoadInteger(...)
```

五槽写盘必须直接挂在这个保存成功回调中：

```jass
call AutoSlot_SaveCurrent(Ii1o)
```

该调用位于旧文本输出判断之后，但不属于判断内部：

```jass
if FM[llql[Ii1o]]!=null and T!=2 then
    call i9pii(Ii1o)
endif
call AutoSlot_SaveCurrent(Ii1o)
```

不能只把 `AutoSlot_SaveCurrent` 放进 `i9pii`。`i9pii` 在 `T == 2` 等运行模式下会被跳过，会出现游戏提示保存完成、但槽位文件没有生成的问题。

`AutoSlot_SaveCurrent` 的写入条件：

- 当前槽位为 1 到 5。
- 保存进程和代码存储对象有效。
- 当前是职业存档，即 `dM[proc] == 1`。
- 不是原系统的服务器保存分支。

当前 0.94a 保存结构映射：

- 玩家：`llll[p90o]`
- 玩家编号：`llol[p90o]`
- 当前保存进程：`llql[p90o]`
- 存档类型：`dM[proc]`
- 代码存储对象：`gM[proc]`
- 代码段数量：`SB[save]`
- 代码段表：`sB[save]`

写入顺序：

1. 写入 `slotN_count.pld`。
2. 写入 `slotN_meta.pld`。
3. 遍历 `SB[save]`，将 `LoadStr(Nv, sB[save], index)` 写入各个 `slotN_codeX.pld`。
4. 向玩家显示本地槽位保存成功提示。

如果已绑定本地槽位，旧文本输出可用时会改写到 `slotN_view.txt`，不再写原来的角色名 TXT 文件。

## 字符串写入与读取

`AutoSlot_SaveStr` 使用 `PreloadGenStart`、`Preload` 和 `PreloadGenEnd` 写入 `.pld` 文件。

字符串以 30 个字符为一段，临时放入 `Player(6)` 到 `Player(15)` 的玩家名中。分片数量通过 `Player(14)` 的科技上限保存。

`AutoSlot_LoadStr` 的读取步骤：

1. 调用 `Preloader` 执行对应 `.pld` 文件。
2. 从 `Player(14)` 的科技上限读取分片数量。
3. 拼接 `Player(6)` 到 `Player(15)` 的名字。
4. 恢复所有临时玩家名。
5. 返回完整字符串。

本地文件只能由本地玩家读取，读取结果不能直接修改同步游戏状态。

## 读取与同步流程

`AutoSlot_StartLoad` 只在槽位所属玩家的本地客户端执行：

1. 读取 `slotN_count.pld`。
2. 逐个读取 `slotN_codeX.pld`。
3. 检查代码段是否为空或不完整。
4. 使用 `DzSyncData("twslotload", data)` 将代码同步给所有客户端。

同步数据格式：

```text
playerId|slot|index|count:saveCode
```

`AutoSlot_OnSync` 收到数据后会：

1. 解析玩家、槽位、段序号和总段数。
2. 校验同步发送者与数据中的玩家编号一致。
3. 用 `playerId * 10 + slot` 作为 Hashtable parent key。
4. 缓存各段存档代码。
5. 收齐全部代码后调用 `AutoSlot_BeginLoad`。

## 接入原读档系统

当前 0.94a 的原读档接口与旧版混淆函数名不同，实际映射为：

- `iqp_i(playerId)`：创建并初始化读档进程。
- `iqpui(playerId, 1, true, false, null)`：加入职业读档任务。
- `iqpii(playerId, saveCode, true)`：向原读档器提交一段完整代码。

`AutoSlot_BeginLoad` 不自行创建英雄或恢复装备，而是依次调用这些原始接口。版本、CRC、玩家身份、英雄、装备和属性恢复仍由地图原读档系统处理。

这是多人同步的必要条件：只有本地文件读取发生在本地分支，真正改变游戏状态的原读档流程由所有客户端共同执行。

## 测试步骤

每次修改后必须重新生成独立测试地图，不能直接运行未回写的原图。

建议测试顺序：

1. 使用 `世界RPG v0.94a-五槽测试.w3x` 进入游戏。
2. 在开局菜单选择一个空槽位。
3. 点击“使用该存档新建角色”。
4. 选择英雄，确认新英雄为 100 级。
5. 输入 `-save`，等待原系统提示保存完成。
6. 确认生成 `slotN_count.pld`、`slotN_meta.pld` 和至少一个 `slotN_codeX.pld`。
7. 退出并重新进入同一张测试地图。
8. 选择同一槽位并点击“加载角色”。
9. 确认英雄、等级、装备和属性由原读档流程恢复。

多人测试还需要确认：

- 每位玩家只能读取自己的本地文件。
- 同步后所有客户端看到的英雄和属性一致。
- 同时读取不同槽位不会串号。
- 缺失或损坏的代码段只提示错误，不进入半完成的读档状态。

## 静态验证

修改后至少执行：

- `pjass` 完整语法检查。
- 生成测试地图。
- 从测试地图重新导出 `war3map.j`。
- 比较重新导出的脚本与 `s2/data/war3map.j` 的 SHA-256。

静态检查和脚本哈希一致只能证明代码已经正确打包，不能代替 Warcraft III 客户端中的写盘和同步读档测试。
